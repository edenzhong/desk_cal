# 任务拆分和开发计划

## 概述
本文档将桌面日历项目拆分为多个开发阶段，每个阶段产出可验收的成果，确保项目在正确方向上推进，避免过度投入错误方案。

## 开发原则
1. **渐进式开发**：每个阶段聚焦有限功能，快速验证
2. **持续验收**：每阶段结束后进行功能演示和用户反馈
3. **技术风险前置**：将不确定的技术挑战（如窗口层级）放在早期阶段验证
4. **迭代优化**：界面美观等主观需求通过多次迭代完善

## 阶段规划

### 阶段 0：环境准备和原型验证（预计：1-2天）
**目标**：验证动态墙纸方案可行性，建立开发环境，创建最小可行原型

**任务**：
1. [ ] 使用 Swift Package Manager 创建可执行项目：`swift package init --type executable --name DeskCal`
2. [ ] 配置项目：设置 macOS 部署目标（11.0+），添加必要的框架依赖
3. [ ] 实现基础图片生成：使用 Core Graphics 创建简单图片
4. [ ] 实现墙纸设置：使用 NSWorkspace 将图片设置为桌面墙纸
5. [ ] 验证图片生成和墙纸设置流程正常工作
6. [ ] 测试多显示器支持：为主显示器设置墙纸
7. [ ] 编写环境配置文档

**验收标准**：
- 使用 SPM 成功创建可编译的项目结构
- 应用能生成简单图片（如纯色背景 + "Hello Calendar"）
- 图片能成功设置为桌面墙纸
- 墙纸设置不影响系统正常功能
- 仅主显示器墙纸被修改（扩展显示器保持不变）
- 无内存泄漏，可正常退出

**产出**：
- Swift Package Manager 项目文件（Package.swift 等）
- 基础图片生成和墙纸设置原型
- 环境配置文档

### 阶段 1：基础日历图片生成（预计：2-3天）
**目标**：实现单个月份的日历图片生成，验证日期计算和 Core Graphics 绘图

**任务**：
1. [x] 创建 `DateCalculator`：计算月份天数、星期排列、闰年处理
2. [x] 实现 `CalendarGenerator` 基础框架：创建绘图上下文，管理图形状态
3. [x] 实现单个月份绘制：月份标题、星期标题、日期网格
4. [x] 添加今日日期高亮（简单圆圈或背景色）
5. [x] 集成到原型应用，生成单月日历图片并设置为墙纸
6. [x] 测试不同分辨率屏幕的适配性

**验收标准**：
- 正确生成当前月份的日历图片
- 日期排列正确（从周一开始，空白单元格处理）
- 今天日期有明显视觉区分（高亮）
- 图片分辨率适配屏幕（考虑 Retina 显示）
- 闰年、月份天数计算正确
- 图片生成性能可接受（< 1秒）

**产出**：
- 日期计算核心模块
- 基础日历图片生成器
- 可生成单月日历墙纸的应用

### 阶段 2：全年日历和布局优化（预计：2-3天）
**目标**：扩展为全年日历图片生成，实现响应式布局和屏幕适配

**任务**：
1. [x] 扩展 `CalendarGenerator` 支持全年数据（12个月）
2. [x] 实现 `LayoutCalculator`：根据屏幕尺寸计算最优月份布局
3. [x] 动态月份列数：大屏幕4列，中等3列，小屏幕2列
4. [x] 实现响应式字体大小：基于可用空间调整文字大小
5. [x] 优化图片生成性能：缓存计算结果，减少重复绘图
6. [x] 集成全年日历生成到应用，测试不同屏幕尺寸

**验收标准**：
- 正确生成包含12个月份的全年日历图片
- 不同屏幕分辨率下布局合理（列数自适应）
- 字体大小可读，间距适当
- 图片生成时间合理（< 3秒）
- 高分辨率屏幕（Retina）图片清晰无模糊
- 内存使用合理，无泄漏

**产出**：
- 布局计算模块
- 全年日历图片生成器
- 响应式布局适配方案

### 阶段 3：定时更新和系统集成（预计：2天）
**目标**：实现自动定时更新，完善系统集成和错误处理

**任务**：
1. [ ] 创建 `WallpaperScheduler`：管理定时任务，每天触发更新
2. [ ] 实现日期变化检测：跨天、跨月、跨年时自动重新生成
3. [ ] 完善 `WallpaperManager`：错误处理，权限检查，恢复机制
4. [ ] 添加屏幕变化监听：显示器连接/断开时自动适配
5. [ ] 实现日志系统：记录更新状态和错误信息
6. [ ] 测试长时间运行稳定性（24小时+）

**验收标准**：
- 每天自动更新墙纸，确保日期准确
- 日期变化时（午夜）及时更新（< 5分钟延迟）
- 屏幕配置变化时自动重新生成适配图片
- 错误情况得到妥善处理，应用不崩溃
- 日志记录完整，便于问题排查
- 资源占用低，不影响系统性能

**产出**：
- 定时调度模块
- 错误处理系统
- 日志记录功能

### 阶段 4：界面美化和视觉优化（预计：3-4天）
**目标**：提升日历图片的视觉质量，优化样式，添加美观效果

**任务**：
1. [ ] 设计视觉样式系统：参考 macOS 系统日历，选择协调的颜色方案
2. [ ] 优化字体渲染：使用系统字体（San Francisco），建立字体层级
3. [ ] 增强今日高亮效果：圆形背景、阴影、渐变等视觉效果
4. [ ] 添加视觉元素：月份分隔线、年份标题、装饰性图形
5. [ ] 优化抗锯齿和子像素渲染，确保文字清晰
6. [ ] 支持透明背景选项，与用户墙纸更好融合
7. [ ] 用户测试和反馈收集，调整视觉效果

**验收标准**：
- 日历美观，风格与 macOS 系统日历协调
- 颜色对比度足够，在各种墙纸背景下都可读
- 文字清晰锐利，特别是高分辨率屏幕
- 今日日期突出但不突兀
- 整体视觉效果令人满意，用户反馈积极
- 图片生成质量高，无明显瑕疵或锯齿

**产出**：
- 完善的视觉样式系统
- 高质量的日历图片生成
- 用户反馈报告和优化方案

### 阶段 5：用户控制和发布准备（预计：2-3天）
**目标**：添加用户控制功能，完善应用体验，准备发布版本

**任务**：
1. [ ] 实现命令行控制接口：启动/停止服务、手动更新、查看状态
2. [ ] 实现配置文件系统：支持基本设置（如是否显示周末颜色、更新频率）
3. [ ] 添加开机自启动选项，配置为登录项（通过 launchd 或登录项）
4. [ ] 编写用户文档：README、使用说明、配置示例、故障排除
5. [ ] 打包应用：可执行文件 + 配置文件模板 + 安装脚本
6. [ ] 全面测试：不同 macOS 版本、不同显示器配置
7. [ ] 创建安装/卸载脚本，确保干净安装和移除

**验收标准**：
- 用户可通过命令行方便地控制应用
- 支持开机自启动，用户登录后自动运行
- 有配置文件系统，满足常见需求
- 应用稳定，在不同环境下测试通过
- 安装包简单易用，卸载干净彻底
- 文档齐全，帮助用户快速上手

**产出**：
- 可分发应用包（可执行文件 + 配置模板 + 安装脚本）
- 完整用户文档
- 安装和卸载脚本
- 测试报告

## 开发顺序建议
```
阶段0 → 阶段1 → 阶段2 → 阶段3 → 阶段4 → 阶段5
      │        │        │        │        │
     原型验证  单月生成  全年布局  定时更新  视觉优化  发布准备
```

**关键路径**：
- 阶段0必须首先完成，验证动态墙纸方案可行性
- 阶段1（单月生成）是阶段2（全年布局）的基础
- 阶段3（定时更新）依赖于阶段1-2的图片生成功能
- 阶段4（视觉优化）在功能稳定后进行，专注于用户体验
- 阶段5（发布准备）在所有功能完成并测试后进行

## 风险评估和应对

| 风险 | 可能阶段 | 应对措施 |
|------|----------|----------|
| 墙纸设置 API 限制 | 阶段0 | 研究替代方案：脚本工具、辅助功能、第三方库 |
| 图片生成性能问题 | 阶段1-2 | 优化 Core Graphics 代码，缓存计算结果，后台生成 |
| 多显示器适配复杂 | 阶段0-2 | 简化需求：仅主显示器，后续逐步扩展 |
| 定时任务可靠性 | 阶段3 | 使用系统级定时器，添加监控和重试机制 |
| 视觉效果不满意 | 阶段4 | 参考系统日历设计，进行用户测试和迭代优化 |
| 用户墙纸冲突 | 阶段0-5 | 提供透明背景选项，允许用户恢复原始墙纸 |
| 无图形界面开发困难 | 阶段0-5 | 使用命令行工具、日志调试、简化用户界面需求 |
